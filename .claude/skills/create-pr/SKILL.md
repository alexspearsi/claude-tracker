# Создание PR по аргументам

Аргументы вызова: `<название-ветки> <заголовок PR>` (заголовок — всё после имени ветки,
может содержать пробелы). Если аргумент не передан — спроси недостающее у пользователя,
не придумывай сам.

Правила веток, коммитов и оформления PR — по скиллу `commit`
(`.claude/skills/commit/SKILL.md`), обращайся к нему за деталями GitHub Flow и
Conventional Commits. Этот скилл — только про сам вызов `gh pr create`.

## Шаги

1. **Проверь состояние репозитория.** `git status` — если есть незакоммиченные изменения,
   спроси пользователя, коммитить их перед созданием PR или нет (не коммить и не отбрасывай
   молча).

2. **Определи ветку.**
   - Если переданное имя ветки совпадает с текущей (`git branch --show-current`) — работай
     в ней.
   - Если ветки с таким именем не существует — создай её от актуального `master`:
     `git checkout master && git pull && git checkout -b <ветка>`.
   - Если ветка существует, но не текущая — переключись на неё (`git checkout <ветка>`),
     предварительно убедившись, что текущие изменения не потеряются (см. шаг 1).

3. **Запушь ветку**, если она ещё не на origin или есть новые коммиты:
   `git push -u origin <ветка>`.

4. **Собери описание PR перед вызовом `gh pr create`.** Обязательно посмотри
   `git diff master...HEAD` и `git log master..HEAD`, а не только последний коммит — тело
   PR должно перечислять реализованное по всей ветке. Формат тела:
   ```
   ## Summary
   - ...

   ## Test plan
   - [ ] ...
   ```

5. **Создай PR** переданным заголовком:
   ```bash
   gh pr create --title "<заголовок>" --base master --head <ветка> --body "$(cat <<'EOF'
   ## Summary
   - ...

   ## Test plan
   - [ ] ...
   EOF
   )"
   ```

6. **Верни пользователю ссылку на PR**, которую выводит `gh pr create`.

## Важно

- Не пушь force и не переписывай историю без явной просьбы.
- Не создавай PR в ветку, отличную от `master`, если пользователь явно не попросил другую
  base-ветку.
- Если `gh` не авторизован (`gh auth status` падает) — сообщи пользователю и предложи
  выполнить `gh auth login` самостоятельно (через `! gh auth login` в чате), не пытайся
  логиниться сам.

# Requirements — Expense Tracker (CRUD milestone)

Источник: `.planning/PROJECT.md` (Active requirements) + `.planning/research/` (FEATURES.md).

## v1 Requirements

### Транзакции (TXN)

- [ ] **TXN-01**: Пользователь может добавить транзакцию (доход или расход) — тип
      (переключатель, не select), сумма, категория, дата (по умолчанию сегодня),
      необязательное описание
- [ ] **TXN-02**: Пользователь может отредактировать существующую транзакцию —
      форма предзаполнена текущими значениями
- [ ] **TXN-03**: Пользователь может удалить транзакцию с подтверждением
- [ ] **TXN-04**: Страница `/expenses` показывает полный список транзакций
      пользователя с пагинацией (не заглушка)
- [ ] **TXN-05**: Быстрое добавление транзакции доступно с `/dashboard` —
      использует ту же форму, что и `/expenses` (одна общая `features/transaction`,
      а не два независимых компонента)
- [x] **TXN-06**: Список транзакций можно фильтровать по периоду, типу
      (доход/расход) и категории — на основе уже существующих фильтров API

### Категории (CAT)

- [x] **CAT-01**: Пользователь может создать категорию (название + цвет из
      предустановленной палитры)
- [x] **CAT-02**: Пользователь может отредактировать существующую категорию
- [x] **CAT-03**: Пользователь может удалить категорию с подтверждением
- [x] **CAT-04**: Если у категории есть связанные транзакции, удаление
      блокируется и показывается понятное сообщение (маппинг API-ответа 409,
      а не сырой текст ошибки)
- [x] **CAT-05**: Страница `/categories` работает как полноценный список с
      CRUD (не заглушка)

### Сводка и баланс (SUM)

- [ ] **SUM-01**: Пользователь видит сводку баланса/доходов/расходов за
      текущий месяц на дашборде (на основе `GET /transactions/summary`)
- [ ] **SUM-02**: Пользователь видит разбивку доходов/расходов по категориям
      в виде таблицы (сумма, категория, цвет), отсортированной по убыванию
      суммы — без графиков

## Out of Scope

- Мультивалюта/конвертация — не нужна для одного пользователя в рамках этой версии
- Повторяющиеся транзакции (по расписанию) — отдельная задача, требует своей
  модели данных и семантики редактирования
- Бюджеты/лимиты расходов по категориям — отдельная задача, требует модели
  лимитов и логики оповещений
- Экспорт/импорт данных (CSV/Excel) — отдельная задача, требует решения по
  формату и логике валидации/дедупликации при импорте
- Визуализация графиками (круговые/столбчатые диаграммы) — начинаем с
  простой таблицы, графики можно добавить позже отдельным милстоуном
- Полноценный color picker (HSB/RGB) для категорий — достаточно
  предустановленной палитры (8–12 цветов)

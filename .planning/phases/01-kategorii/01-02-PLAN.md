<objective>
Достроить срез категорий до полного CRUD: редактирование существующей категории через ту же
форму (CAT-02), удаление с подтверждением (CAT-03) и понятная блокировка удаления категории,
на которую ссылаются транзакции (CAT-04).

Реализует D-02 (одна `CategoryForm` на создание и редактирование — здесь включается ветка
редактирования), D-04 (обычные кнопки действий в строке, без `DropdownMenu`),
D-05 (`AlertDialog` для подтверждения) и D-06 (при 409 сообщение показывается в самом
диалоге, диалог не закрывается молча).

Purpose: расширение проверенного в плане 01-01 пути — архитектура среза уже доказана, здесь
добавляются два новых глагола на том же маршруте.
Output: `/categories` работает как полноценный CRUD, включая корректное поведение на
конфликте внешнего ключа.

Backend не меняется: `PATCH /categories/:id` и `DELETE /categories/:id` уже реализованы,
`P2003` уже переводится в 409 (`ConflictException`) в `categories.service.ts`.
</objective>

Вертикальный срез «отредактировать категорию» целиком: от кнопки в строке до
`PATCH /api/categories/:id` и обратно через `revalidatePath`. Комментарии — на русском.

**1. `apps/web/src/entities/category/api/update-category.ts`.** Форма — как у
`create-category.ts` из плана 01-01: `import 'server-only'` первой строкой, `accessToken`
первым параметром, `getSession` внутри не звать.
Сигнатура: `export function updateCategory(accessToken: string, id: string, input: UpdateCategoryInput): Promise<Category>`,
тело — `apiFetch<Category>(\`/categories/${id}\`, { method: 'PATCH', accessToken, body: JSON.stringify(input) })`.

**2. `apps/web/src/features/category-form/api/update-category.action.ts`.** Копия структуры
`create-category.action.ts`, отличия только в схеме, вызове entity и сигнатуре:
`export async function updateCategoryAction(id: string, input: unknown): Promise<CategoryActionState>`.
Шаги: `updateCategorySchema.safeParse(input)` → при неудаче `{ error: 'Проверьте правильность заполнения полей' }`;
`await getSession()` → при отсутствии `{ error: 'Сессия истекла, войдите заново' }`;
`try { await updateCategory(session.accessToken, id, parsed.data) } catch (error) { ... }` —
в `catch` сначала `extractFieldErrors(error)` (если не `null` → `{ error: 'Проверьте правильность заполнения полей', fieldErrors }`),
иначе `{ error: apiErrorMessage(error) }`; затем
`for (const path of CATEGORY_AFFECTED_PATHS) revalidatePath(path)` и `return { success: true }`.
`redirect()` не использовать.
Форма всегда отправляет обе пары `name` и `color`, поэтому строить обобщённый «убиратель
пустых ключей» не нужно и вредно: `UpdateCategoryDto` на сервере принимает отсутствие поля, но
отвергает явный `null` для `name`/`color` (там `NOT NULL`-колонки и собственный гард
`isPresent` вместо `@IsOptional`). Слать ровно то, что вернул `safeParse`.

**3. `apps/web/src/features/category-form/ui/category-form.tsx`.** Включить ветку
редактирования на уже существующем пропе `category?: Category` (D-02):
- `defaultValues: category ? { name: category.name, color: category.color } : { name: '', color: CATEGORY_COLORS[0] }`.
  `icon` не засеивать и не выводить — в ответе API он `string | null`, а в схеме создания

- Резолвер остаётся `zodResolver(createCategorySchema)` для обоих режимов: оба поля в форме

  уже в экшене.
- В `onSubmit`: `const result = category ? await updateCategoryAction(category.id, values) : await createCategoryAction(values)`.

Второй вертикальный срез: «удалить категорию» от кнопки в строке до `DELETE /api/categories/:id`.
Ветка блокировки на 409 — отдельная задача 3; здесь делается счастливый путь и общая обработка
ошибок. Комментарии — на русском.

**1. Сгенерировать shadcn `AlertDialog`.** В каталоге `apps/web`:
`npx shadcn@latest add alert-dialog`. После генерации проверить
`apps/web/src/shared/ui/alert-dialog.tsx` теми же критериями, что применялись к `dialog.tsx` в
плане 01-01: примитив импортируется из объединённого пакета `radix-ui`, хелпер `cn` —
из `@/shared/lib/utils`, `apps/web/package.json` не изменился. Если манифест изменился —
остановиться и разобраться до коммита, ориентир — `## Package Legitimacy Audit` в
01-RESEARCH.md и раздел про shadcn CLI в `.claude/CLAUDE.md`.

**2. `apps/web/src/entities/category/api/delete-category.ts`.** `import 'server-only'` первой
строкой, `accessToken` первым параметром.
Сигнатура: `export function deleteCategory(accessToken: string, id: string): Promise<void>`,
тело — `apiFetch<void>(\`/categories/${id}\`, { method: 'DELETE', accessToken })`.
Особый разбор `204 No Content` не нужен: `apiFetch` уже отдаёт `null` при 204 вместо попытки
разобрать пустое тело как JSON.

**3. `apps/web/src/features/category-form/api/delete-category.action.ts`.** Готовый код есть в
01-RESEARCH.md «Pattern 4» — скопировать оттуда.
`export async function deleteCategoryAction(id: string): Promise<CategoryActionState>`.
Шаги: `await getSession()` → при отсутствии `{ error: 'Сессия истекла, войдите заново' }`;
`try { await deleteCategory(session.accessToken, id) } catch (error) { ... }`; после успеха —
`for (const path of CATEGORY_AFFECTED_PATHS) revalidatePath(path)` и `return { success: true }`.
Схему тут парсить нечего — на входе только `id`, его формат проверяет `ParseUUIDPipe` на
сервере. В `catch` на этом шаге — только общий `{ error: apiErrorMessage(error) }`; ветку 409
добавляет задача 3.

**4. `apps/web/src/features/category-form/ui/category-delete-dialog.tsx`.** `'use client'`.
Прямого аналога в репозитории нет — это первое использование `AlertDialog`; идиома ветвления
берётся из `features/auth/api/logout.action.ts` (`error instanceof ApiError && error.status === N`).
Пропсы: `{ category: Category; open: boolean; onOpenChange: (open: boolean) => void }`.
Разметка (D-05, тексты дословно из 01-UI-SPEC.md `## Copywriting Contract`):
`AlertDialog` управляемый через `open`/`onOpenChange`; `AlertDialogTitle` —
`Удалить категорию «{category.name}»?`; `AlertDialogDescription` — «Это действие нельзя отменить.»;
`AlertDialogCancel` — «Отмена»; `AlertDialogAction` — «Удалить», оформленная как разрушающее
действие (класс из `buttonVariants({ variant: 'destructive' })`).
Локальное состояние `const [isPending, setIsPending] = useState(false)`; кнопка подтверждения
`disabled={isPending}` и показывает `Loader2Icon` с `animate-spin`, пока идёт запрос — тот же

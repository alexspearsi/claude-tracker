## Spacing Scale

Declared values (must be multiples of 4) — unchanged from the project's existing convention
(`dashboard-view.tsx`, `login-view.tsx` etc. already use this scale; not a new decision):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (e.g. `CategoryDot` to name) |
| sm | 8px | Compact spacing — swatch grid gaps, row action button gaps |
| md | 16px | Default element spacing — form field gaps (`grid gap-4`, matches `register-form.tsx`) |
| lg | 24px | Section padding — page container `gap-6`/`p-6` (matches `dashboard-view.tsx`) |
| xl | 32px | Not used this phase (no layout gap of this size needed) |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions: none. Row-action and Dialog-trigger buttons use the existing `size="sm"`/`size="icon-sm"`
variants (32px, `h-8`/`size-8`) already defined in `button.tsx` — no new touch-target size is
introduced; this is a desktop-first web app with no mobile-specific requirement in
REQUIREMENTS.md, so the project's existing 36px (`size="default"`) / 32px (`size="sm"`) button
scale is reused as-is rather than widened to a 44px mobile touch target.

## Color

Values are given in this project's actual token space (`oklch`, defined in
`apps/web/src/app/globals.css` `:root`) rather than invented hex — the template's "hex" column
header does not apply to this codebase's Tailwind v4 CSS-variable theme.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` — `oklch(1 0 0)` light / `oklch(0.21 0.03 264)` dark | Page background (`<main>`), the majority surface |
| Secondary (30%) | `--card` / `--secondary` / `--muted` — `oklch(0.97 0.01 264)` light / `oklch(0.27–0.28 0.03 264)` dark | Category list container (`Card`, if used) or `Table` header row background, `AlertDialog`/`Dialog` surfaces |
| Accent (10%) | `--primary` — `oklch(0.55 0.19 259)` light / `oklch(0.71 0.14 255)` dark | Reserved for: the primary CTA button ("Создать категорию"), the Dialog's submit button, links (empty-state "Создать категорию" link/button), focus rings (`--ring`, same hue), and the selected-swatch indicator ring in `ColorSwatchPicker` |
| Destructive | `--destructive` — `oklch(0.58 0.24 28)` light / `oklch(0.7 0.19 22)` dark | Reserved for: the "Удалить" row button (`variant="destructive"` or `variant="ghost"` with destructive text color) and the `AlertDialogAction` confirm-delete button only — never used for the 409-blocked inline message text, which uses default `text-destructive` on a `<p>` (same treatment as existing form-error text, not a button) |

Accent reserved for: primary CTA button, Dialog submit button, empty-state CTA, focus rings,
selected color-swatch ring — never for the category swatch colors themselves (those are
user/palette-chosen data, not UI accent) and never for row-level edit/delete buttons (those stay
`variant="ghost"`/`variant="outline"`/`variant="destructive"` per existing button variants, not
tinted primary).

**Palette (the 10 preset category colors, D-03, Claude's discretion):** these are *data* colors
(user-selectable category identity), not part of the 60/30/10 UI-chrome split above — kept
separate deliberately so no user-chosen category color is ever confused with the app's own accent
color:

`#ef4444` (red), `#f97316` (orange), `#f59e0b` (amber), `#22c55e` (green), `#14b8a6` (teal),
`#0ea5e9` (sky), `#3b82f6` (blue), `#6366f1` (indigo), `#8b5cf6` (violet), `#ec4899` (pink).

Rationale for reuse from 01-RESEARCH.md: Tailwind's standard 500-shade scale, mutually distinct,
and distinct from the two grays already used for "no category"/default states (`#64748b`
slate-500 DB default, `#94a3b8` slate-400 dashboard fallback) so a user pick is never mistaken for
"uncategorized." `[ASSUMED — same disclaimer as RESEARCH.md Assumption A1: verify visually
in-browser during execution, since Tailwind v4's actual theme is defined in `oklch()` not hex;
functional risk is zero either way since any `#RRGGBB` value satisfies the schema regex.]`

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Создать категорию" — used for **both** the page-header trigger and the empty-state button (see rationale below) |
| Empty state heading | "Пока нет категорий" (mirrors the existing "Пока нет транзакций" pattern in `widgets/recent-transactions/ui/recent-transactions.tsx`) |
| Empty state body | "Создайте первую категорию, чтобы группировать доходы и расходы" — followed by the "Создать категорию" button (D-07) |
| Error state (list load failure) | "Не удалось загрузить категории: {message}" — exact structural mirror of `dashboard-view.tsx`'s `"Не удалось загрузить данные: {message}"` |
| Error state (field validation, inline) | Per-field message under the offending input via `FormMessage`, sourced from `extractFieldErrors()` (01-RESEARCH.md Pattern 3) — e.g. under Name: the DTO's own message text (`class-validator`-generated, already Russian per existing DTOs) |
| Error state (toast — general/duplicate-name 409) | Whatever `apiErrorMessage()` returns as-is (e.g. "Категория с таким названием уже есть") — do not build a second copy layer on top of the API's own message for this case (01-RESEARCH.md Pitfall 2) |
| Destructive confirmation (delete) | Title: "Удалить категорию «{name}»?" — Body: "Это действие нельзя отменить." — Confirm button: "Удалить" (`variant="destructive"`) — Cancel button: "Отмена" |
| Destructive confirmation — 409 blocked (D-06) | Inline message replacing/appended within the still-open `AlertDialog`: "Нельзя удалить категорию — есть связанные транзакции" (verbatim from D-06) — the dialog does **not** close; the confirm button returns to its idle (non-loading) state so the user can press "Отмена" to back out |

**Rationale for unifying the CTA label:** 01-CONTEXT.md's D-07 locks "Создать категорию" as the
literal empty-state button copy. 01-RESEARCH.md's code sketch separately suggested "Добавить
категорию" for the page-header trigger, but that was a research-time placeholder, not a locked
decision — CONTEXT.md's `code_context` explicitly leaves header-button copy unspecified. Using one
label for both entry points (rather than two near-synonyms) avoids an inconsistent-CTA finding
under Dimension 1 (Copywriting) and gives the user one verb to learn for "start creating a
category," regardless of which button they clicked.

| long-text | category-form | 🧪 backstop | The `Input` for name must not visually overflow its `Dialog` container at 50 characters — rely on the `Input` component's existing `w-full` sizing (already correct by default) plus the schema's `max(50)`/`maxLength={50}` cap; held-out visual check during manual UAT, same reason as above |

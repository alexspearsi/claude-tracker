<objective>
Сквозной вертикальный срез категорий: страница `/categories` перестаёт быть заглушкой и
начинает показывать реальный список категорий пользователя, а кнопка «Создать категорию»
открывает `Dialog` с формой (имя + палитра свотчей), которая реально создаёт категорию
через уже готовый `POST /api/categories` и сразу отражает её в списке.

Закрывает CAT-05 (рабочий список вместо заглушки) и CAT-01 (создание категории с цветом из
предустановленной палитры). Реализует D-01 (`Dialog`), D-02 (одна форма `CategoryForm` с
опциональным пропом `category` — в этом плане задействован только режим создания),
D-03 (фиксированная палитра свотчей), D-04 (простая таблица, `CategoryDot`, без карточек)
и D-07 (пустое состояние).

Purpose: доказать всю архитектуру среза сразу — `app → views → widgets → features → entities
→ shared` + Server Action + `revalidatePath` — на одном живом пути, до того как на неё
навешиваются редактирование и удаление (план 02).
Output: рабочая страница `/categories` с созданием категорий и корректными per-field
ошибками валидации.

Backend не меняется: `/api/categories` полностью реализован (`CategoriesController`,
`CategoriesService`, DTO на class-validator, 409 на `P2002`/`P2003`).
</objective>

| браузер → Server Action | Server Action в Next доступен прямым POST по своему id — тело приходит от недоверенного клиента, валидация в форме его не защищает |

# Phase 3 — UI Design Contract

> Visual and interaction contract for `widgets/monthly-summary`: the three-stat row
> (Баланс/Доходы/Расходы) and the combined category-breakdown table that sits above
> `RecentTransactions` on `/dashboard`. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker. This phase runs entirely within the design system established by
> `01-UI-SPEC.md` and extended by `02-UI-SPEC.md` — **this spec extends both rather than
> re-deriving them**: spacing, typography, color tokens and CTA-unification convention are
> inherited unchanged; only the stat-card layout, the combined-table row language, and the
> empty-state copy (all left to "Claude's discretion" by `03-CONTEXT.md`) are new content below.
> No `AskUserQuestion` was used — `03-CONTEXT.md` was itself produced in `--auto` mode, and the
> two remaining discretion items it deferred to this phase are resolved here directly.

## Layout

> Not a template section header on its own in other phase specs, but this phase's core visual
> decision — documented explicitly so the executor has one exact target, not a range.

**Structure — one `Card`, top to bottom:**

```
<Card>
  <CardHeader>
    <CardTitle>Сводка за месяц</CardTitle>
  </CardHeader>
  <CardContent className="flex flex-col gap-4">

    {/* Zone 1 — three stat cards */}
    <div className="grid grid-cols-3 gap-4">
      <SummaryStat label="Баланс"  amount={balance} />                                  {/* neutral */}
      <SummaryStat label="Доходы"  amount={income}  colorClassName="text-emerald-600 dark:text-emerald-400" />
      <SummaryStat label="Расходы" amount={expense} colorClassName="text-destructive" />
    </div>

    {/* Zone 2 — category breakdown, separated by a divider */}
    <div className="flex flex-col gap-4 border-t pt-4">
      <h2 className="text-sm font-medium">По категориям</h2>
      {byCategory.length === 0 ? (
        <p className="text-sm text-muted-foreground">Нет данных за текущий месяц</p>
      ) : (
        <SummaryCategoryTable items={byCategory} />
      )}
    </div>

  </CardContent>
</Card>
```

**Order rationale (D-01, D-03 read together):** Баланс is listed first (leftmost column) — it is
the single number that answers "how am I doing," and leftmost-in-a-3-column-grid is the first
thing a left-to-right reader's eye lands on. Доходы/Расходы follow in the same order the decision
text lists them ("доходы и расходы"), each carrying its own semantic color (green/red) which
gives them a secondary, color-driven pull on the eye — Баланс stays typographically identical in
size/weight to the other two (no size bump) and is differentiated **only** by position and the
absence of color, per D-03's explicit instruction not to imply a value judgment.

**Stat card internals** (`SummaryStat`, one per column):
```tsx
<div className="flex flex-col gap-1">
  <span className="text-sm text-muted-foreground">{label}</span>
  <span className={cn('text-2xl font-semibold tabular-nums', colorClassName)}>
    {formatMoney(amount)}
  </span>
</div>
```
No `+`/`−` prefix is added on any of the three values (unlike `TransactionAmount`): `income` and
`expense` are non-negative aggregates from the API (never signed), and `balance`'s sign is already
rendered by `formatMoney`'s underlying `Intl.NumberFormat('ru-RU', ...)` — a project-wide fact,
not new this phase (see `03-RESEARCH.md` Pattern 5, Pitfall 4). Adding an explicit prefix to
Доходы/Расходы while Баланс has none (or vice versa) would read as an inconsistency; the rule is
simply "print exactly what `formatMoney` returns, nothing added."

**Category table internals:** see `03-RESEARCH.md` Pattern 6 verbatim — `TransactionAmount`
reused directly, React key `` `${categoryId}-${type}` `` (Pitfall 2), no re-sort on the frontend
(D-05, server order trusted).

## Color

Unchanged from `01-UI-SPEC.md`'s 60/30/10 split and token space (`oklch`,
`apps/web/src/app/globals.css` `:root`) — inherited, not re-derived. **This phase adds zero new
accent (10%) usage** — the widget has no interactive control, so nothing here draws on
`--primary`:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` | Page background — unchanged |
| Secondary (30%) | `--card` | The widget's own `Card` surface — same token as `RecentTransactions`'s `Card`; table rows have **no** distinct header background in this project's `table.tsx` (only a `border-b`), so "Secondary" here means the `Card` container, not a tinted header row |
| Accent (10%) | `--primary` | **Not used by this widget** — no button, no link, no focus target exists inside `MonthlySummary`. Still reserved project-wide for: primary CTAs, form submit buttons, focus rings, selected-day indicators (unchanged from Phase 1/2) |
| Destructive | `--destructive` | Reused for the Расходы stat card text and for `EXPENSE`-type rows in the category table (via `TransactionAmount`) — **not** a new destructive-action usage (no delete/irreversible action exists here), a semantic-amount usage that happens to share the token, exactly as Phase 2 already established for `TransactionAmount` |

**Semantic amount color (D-03 — same separate channel Phase 2 established for
`TransactionAmount`, extended here to the stat cards):**

| Role | Value | Usage |
|------|-------|-------|
| Income | `text-emerald-600` light / `text-emerald-400` dark | Доходы stat card value; `INCOME`-type rows in the category table (via `TransactionAmount`, unchanged) |
| Expense | `--destructive` (`text-destructive`) | Расходы stat card value; `EXPENSE`-type rows in the category table (via `TransactionAmount`, unchanged) |
| **Balance (new this phase)** | **No color class — default `text-foreground`** (inherited from the surrounding `Card`'s text color, no override) | Баланс stat card value. D-03's explicit requirement: balance is a fact, not a judgment — it must **not** read as good/bad via color, even when negative. This is a deliberate absence of a semantic-color mapping, not an oversight: do not add `text-red-500`/`text-emerald-500` conditionally on `balance < 0`, that would silently reintroduce the value judgment D-03 forbids |

Accent reserved for: primary CTA, form submit button, active states, focus rings, Calendar
selected-day (Phase 1/2 list, unchanged) — never for the balance/income/expense stat values (a
separate semantic channel) and never introduced by this phase for any element.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Widget card title | "Сводка за месяц" — communicates the "current month, not selectable" scope implicitly (D-02: no period switcher this phase), avoiding a title like "Сводка" alone which could read as if a period picker should be nearby |
| Stat label — balance | "Баланс" |
| Stat label — income | "Доходы" |
| Stat label — expense | "Расходы" |
| Category section subheading | "По категориям" |
| Table header — column 1 | "Категория" |
| Table header — column 2 | "Сумма" (right-aligned, matches `03-RESEARCH.md` Pattern 6) |
| Empty state (zero transactions this month, D-07) | "Нет данных за текущий месяц" — a single line, **not** the two-part heading+body `EmptyState` component `RecentTransactions` uses (that component lives in `widgets/recent-transactions`, cross-importing it into `widgets/monthly-summary` is forbidden by the project's "no cross-imports within a layer" FSD rule — `03-RESEARCH.md` Anti-Pattern). No CTA button here (unlike the true-empty transaction list on `/expenses`): the fix for "no data this month" is "add a transaction," which is already one click away via `QuickAddTransaction` in `RecentTransactions`'s header immediately below — repeating that CTA a second time on the same page would be redundant, not helpful |
| Error state (summary load failure, D-08) | "Не удалось загрузить сводку: {message}" — rendered by `DashboardView`, not by the widget itself (mirrors the exact structural pattern already used for `RecentTransactions`'s own error branch: `"Не удалось загрузить данные: {message}"`) — when this fires, `MonthlySummary` is not rendered at all, so no empty/error copy is needed *inside* the widget for this case |

**Note on the three stat card values themselves:** they are not copy in the traditional sense
(they're `formatMoney(amount)` output, unstyled beyond the color rules above) — no unit suffix,
no "₽" repeated beyond what `Intl.NumberFormat` already renders, no rounding beyond the two
decimal places `formatMoney` already applies project-wide.
